# Contrato: Extracciones de caja (cash withdrawals)

Feature: under each card of "Lo que hay ahora" on Inicio (Efectivo, Transferencia, Dólares, Euros) the OWNER
gets an "Extraer" button with an amount + optional note. Business rules (decided by the shop owner):
1. Only the owner ('dueño') can create or void withdrawals. Cashiers ('cajero') get 403 "Solo el dueño puede extraer dinero".
2. The cash close (arqueo) subtracts open withdrawals from what "debería haber" (expected), so no false shortage.
3. Withdrawing more than the card shows is ALLOWED (UI only warns).
4. A withdrawal can be voided (anulada) only while it is not covered by a cash close. After that it is fixed.
5. Works offline (desktop local SQLite + PWA IndexedDB), syncs later, same as currency purchases ("compra de divisa").
6. Transferencia withdrawal = money left the bank account; lowers the transfer number. USD/EUR are in their own currency.

The existing "currency purchases" (compra de divisa) feature is the pattern to copy in every layer. Read it first.

## Data shape (same field names everywhere: server, desktop local DB, PWA)
Table `cash_withdrawals`:
- id INTEGER PRIMARY KEY AUTOINCREMENT
- user_id INTEGER NOT NULL (shop owner id, like other tables)
- client_withdrawal_id TEXT (UUID generated by the client; UNIQUE per user_id)
- method TEXT NOT NULL — one of 'efectivo' | 'transferencia' | 'USD' | 'EUR'
- amount REAL NOT NULL — > 0, rounded to 2 decimals. CUP for efectivo/transferencia, the foreign currency for USD/EUR
- note TEXT NULL (trimmed, empty → NULL, max 200 chars)
- register_id TEXT NULL (stored like currency purchases, informational only)
- account_id, account_email (who did it; same as currency_purchases)
- cash_close_id INTEGER NULL (set when an arqueo covers it)
- voided_at TEXT NULL (set when anulada; voided rows count as zero everywhere)
- created_at TEXT NOT NULL DEFAULT datetime('now')

`cash_closes` gets 4 new columns, REAL NOT NULL DEFAULT 0:
`withdrawn_cash`, `withdrawn_transfer`, `withdrawn_usd`, `withdrawn_eur` (positive numbers = total withdrawn and covered by that close).

## Shared math (add to server/lib/payment.js, desktop/src/lib/payment.js and client/src/lib/payment.js, identical logic)
```js
const WITHDRAWAL_METHODS = ['efectivo', 'transferencia', 'USD', 'EUR'];
// Lo que una extracción le quita a cada apartado. Anulada = no quita nada.
function withdrawalSplit(w) {
  const amount = w.voided_at ? 0 : round2(w.amount);
  return {
    cash: w.method === 'efectivo' ? -amount : 0,
    transfer: w.method === 'transferencia' ? -amount : 0,
    usd: w.method === 'USD' ? -amount : 0,
    eur: w.method === 'EUR' ? -amount : 0,
  };
}
// Valida y normaliza; lanza Error con mensaje en español para el dueño.
function withdrawalFields(body) {
  if (!WITHDRAWAL_METHODS.includes(body.method)) throw new Error('Apartado inválido');
  const amount = Number(body.amount);
  if (body.amount == null || body.amount === '' || !Number.isFinite(amount) || round2(amount) <= 0) throw new Error('Falta cuánto dinero se extrae');
  const note = body.note == null ? null : String(body.note).trim().slice(0, 200) || null;
  return { method: body.method, amount: round2(amount), note };
}
```
Export WITHDRAWAL_METHODS, withdrawalSplit, withdrawalFields.

## Coverage rule (IMPORTANT, differs from currency purchases)
A withdrawal is NOT tied to a register for coverage. The NEXT cash close of the shop, of ANY mode
(web, desktop, legacy, cashier or owner), takes ALL open withdrawals: `cash_close_id IS NULL AND voided_at IS NULL`.
Reason: the owner usually withdraws from their phone but the cashier closes the drawer on another device.
expected_cash = float + sales/purchases cash + withdrawalSplit cash (i.e. minus withdrawn cash). Same for transfer/usd/eur.
The close stores withdrawn_cash/transfer/usd/eur (positive totals).

## HTTP API (server; desktop router.js and PWA offline layer must answer the same paths)
- `GET /api/cash-withdrawals` (owner only) → array of rows, newest first. `?date=YYYY-MM-DD` filters by shop day
  (like currency purchases); `?open=1` returns only `cash_close_id IS NULL` rows (including voided ones). Default: last 200.
- `POST /api/cash-withdrawals` (owner only) body `{ client_withdrawal_id (required string), method, amount, note?, withdrawn_at?, register_id? }`
  → 201 row. `withdrawn_at` goes through operationTime() like `sold_at` in purchases. Replay with same client_withdrawal_id → 200 `{...row, idempotent_replay: true}`.
  400 with `{error}` on validation. Missing client_withdrawal_id → 400.
- `POST /api/cash-withdrawals/:clientWithdrawalId/void` (owner only) → 200 row (with voided_at set).
  Already voided → 200 same row (idempotent). Covered by a close (cash_close_id NOT NULL) → 409
  `{ error: 'Esta extracción ya entró en un cierre de caja y no se puede anular' }`. Not found → 404.
  Must be a single conditional UPDATE `... SET voided_at = datetime('now') WHERE ... AND cash_close_id IS NULL AND voided_at IS NULL`, then re-read.
- `GET /api/dashboard` → `holdings` now also subtracts open non-voided withdrawals, and response gets
  `open_withdrawals: [...]` (rows with cash_close_id IS NULL, voided_at IS NULL, newest first) so Inicio can list them with "Anular".
- `POST /api/cash-closes` response row includes the 4 withdrawn_* columns.
- `GET /api/dashboard/day` gets `withdrawals: [...]` (rows created that shop day, including voided).
- Excel export (`/api/reports/export`) gets a sheet "Extracciones" (Fecha, Apartado, Cantidad, Nota, Quién, Estado: 'Anulada' / 'En cierre' / 'Abierta'), and the "Cierres de caja" sheet gets a column "Extraído (efectivo)".
- Desktop down-sync `GET /api/sync/...` (server/routes/sync.js): response adds `cash_withdrawals`: rows with `id > cursors.withdrawal` OR `cash_close_id IS NULL` (so voids of open ones propagate), `cursors.withdrawal`, and every `cash_closes` row adds `covered_withdrawal_ids` (server ids). Accept `after_withdrawal` query param like the others.
- PWA snapshot (`server/routes/pwaSync.js`): owner snapshot adds `cash_withdrawals` (all rows of the shop). `current_period.has_sales` also true if there are open non-voided withdrawals.
